# MX CRM 運用ガイド

## 何のための台帳か

MX（Matrox）・VRi（Visual Research）・GM（GlobalM）関連のお客様・パートナーとの接点はほぼメールと
オンライン会議で、やり取りが Gmail と Notion の議事録に散らばっている。
「誰に・いつ・何をしたか」「今どうなっているか」を1枚で見られる状態にして、
**1ヶ月に一度は全件フォローする**ことを目的にした台帳。

## 前提となる商売の形

**MX・VRi・GM はそれぞれ別メーカー。** 台帳では `メーカー` 列で区別し、複数扱う先には複数付ける。

### MX（Matrox）

- 製品は **OEM 向け製品** と **EU 向け製品** の2種
  - OEM 向け … ORIGIN、ORIGIN Fabric、DSX / LE、Xmio、M264、SDK
  - EU 向け … Monarch EDGE、ConvertIP、AVIO2 / IPMX、VION
- 市場は **放送** か **医療**
- 顧客は **SI（販社）** / **EU（エンドユーザー）** / **OEM**
- 商流は `JM→販社→EU` / `JM→OEM` / `JM→EU`

注意点が2つある。

- **OEM の顧客でも EU 向け製品を買うことがある。** 顧客区分が OEM だからといって
  製品区分が OEM 向けだけになるとは限らないので、実際に扱っている製品を両方付ける
- **OEM と SI を兼ねる先がある**（朋栄、NEC など）。顧客区分は複数選択なので両方付ける。
  商流は単一選択なので主たる方を選び、もう一方はメモに書く

### VRi（Visual Research）

- 製品は **Karisma Illuzon** / **Karisma CG3** / **Karisma Studio**
- 市場は **放送**
- 顧客は **SI（販社）** / **EU（エンドユーザー）**
- 商流は `JM→販社→EU` / `JM→EU`

### GM（GlobalM）

- スイス本社。ライブ伝送・配信のクラウド基盤 **GMX Cloud** を提供
- 市場は **放送**
- 顧客は **EU（エンドユーザー）** / **SI（販社）**
- 山下は日本市場担当として GlobalM 名義でも動く（メール署名は「GlobalMの山下」）
- 日本の商談先は KDDI / ネクシオン / スカパーJSAT / 日本テレビ / フジテレビ / NHK。
  いずれも MX の顧客でもあるので、行は分けず同じ行に `メーカー = MX, GM` を付ける

MX と VRi の起点は JM（ジャパンマテリアル）。JM 自身は `顧客区分 = JM（ディストリビューター）`、
メーカー本体（GlobalM、VRi など）は `顧客区分 = メーカー・ベンダー`、`商流 = —（JM・メーカー本体）` に置く。

## 台帳の入力ルール

| 欄 | 誰が書くか | 書き方 |
| --- | --- | --- |
| 会社名 | 人 | 正式名称。別法人は行を分ける（例：ソニー（放送 / SMOJ）とソニーメディカル） |
| メーカー | 人 | MX / VRi。両方扱う先は両方付ける |
| 顧客区分 | 人 | SI（販社）/ EU（エンドユーザー）/ OEM / JM / メーカー・ベンダー。**複数選択可**（OEM 兼 SI など） |
| 市場 | 人 | 放送 / 医療 |
| 商流 | 人 | 顧客区分に対応：SI→`JM→販社→EU`、OEM→`JM→OEM`、EU→`JM→EU`。EU でも間に販社が入るときは `JM→販社→EU` にして販社名をメモに書く。兼ねる先は主たる方を選ぶ |
| 製品区分 | 人 | MX_OEM向け製品 / MX_EU向け製品 / VRi製品。実際に扱っているものを全部付ける |
| ステータス | 人 | 下表を参照 |
| 優先度 | 人 | A=重点 / B=通常 / C=情報提供のみ |
| 主担当者・メール | 人 | 主たる窓口1〜数名。メールは自動同期のキーになるので必ず入れる |
| 最終接点日 | **自動**（会議は手動） | メールは Gmail から自動更新。会議・訪問は手で入れる |
| 最終アクション | **自動**（会議は手動） | 自動更新分は `[自動更新]` で始まる |
| 次のアクション | 人 | 次にやることを1文で。ここが空の行は要注意 |
| 次回フォロー予定日 | 人＋自動 | 過去日のままなら自動で「最終接点＋30日」に繰り下がる |
| 経過日数 / 要フォロー | 数式 | 触らない |
| 製品・案件 / 接点チャネル | 人 | 絞り込み用 |
| メモ | 人 | 背景・懸念・議事録からの引用 |

### ステータスの使い分け

| ステータス | 状態 |
| --- | --- |
| リード | 名前は分かっているが、まだ双方向のやり取りがない |
| 初回接触 | 挨拶・展示会での名刺交換まで。案件はまだない |
| 商談・提案中 | 具体的な製品・案件の話が動いている |
| 評価・PoC中 | 評価機貸出、検証、キックオフ済み |
| 受注・納入 | PO が出ている / 納入済みで継続取引中 |
| 保留・様子見 | 案件が止まっている。理由をメモに書く |
| クローズ | 失注または取引終了。フォロー対象から外れる |

## 月次フォローアップの手順

毎月1日にダイジェストメールが届く（Notion の「🔴 要フォロー」ビューと同じ内容）。

1. **優先度 A から片づける。** A は重点案件なので、30日空いている時点で遅い。
2. Gmail の下書きフォルダに、A / B 向けのフォローメール下書きが自動生成されている。
   本文末尾の「社内メモ」に前回の「次のアクション」が入っているので、それを起点に本文を書き直し、メモ部分を削除して送る。
3. 送るまでもない相手（クローズ相当）は、ステータスを `クローズ` にする。
   クローズ済みの行は翌月からダイジェストに出なくなる。
4. C 優先度で1年以上動きがない行は、年1回まとめて棚卸しする。

## メール以外の接点を記録する

オンライン会議・訪問・展示会での接触は Gmail に残らない。
**Notion に議事録を残していれば自動で拾われる**が、拾われるのは以下の条件を満たす場合だけ。

- 議事録が `Business > MX` の配下にあるか、インテグレーションが接続されたページであること
- タイトルに会社名（または `Config.gs` の `MEETING_ALIASES` に書いた別名）が入っていること

タイトルに日付が入っていればその日付が、なければページの作成日が最終接点日になる。
`MX_251002_QVC_...`、`2025/07/02`、`@2026年8月3日` のどの書き方でも読み取れる。

議事録を残していない接触は、台帳側で手で更新する。

1. その行を開く
2. **最終接点日** に会議の日付を入れる
3. **最終アクション** に「8/19 オンライン会議。ORIGIN Fabric の評価範囲を確認」のように書く
4. **接点チャネル** に `オンライン会議` などを追加する

手で入れた日付がメール・議事録のどちらより新しい場合、翌朝の自動同期は上書きしない。

## Notion の議事録との使い分け

- 議事録（Business > MX 配下）… 会議の中身そのもの。長文で残す
- この台帳 … 誰と・いつ・今どうなっているかの索引。1行に要約して残す

議事録に重要な決定や課題が出たら、該当行の **メモ** と **次のアクション** に1文で落とす。
最終接点日と最終アクションは自動で入るので、手で書く必要はない。

## データの出どころ

初期データは以下から機械的に集約している。

- Gmail の送受信スレッド（2025年7月〜2026年8月、約1,500通）
- Google カレンダーの会議予定
- Notion の MX 議事録・営業報告書

社名・担当者名の一部はメールアドレスからの推定で、`メモ` 欄に「要確認」と書いてある。
気づいたときに正しい表記へ直す。

顧客区分（SI / EU / OEM）も、やり取りの内容から推定した行がある。判断の根拠が弱いものは
`メモ` に「※顧客区分は要確認」と書いてあるので、実態と違うものは直す。
ここを直すと `商流` も変わる点に注意する。
