# CRM 定期実行（Routine）用プロンプト

claude.ai の **Routines（定期実行）** 画面で新規 Routine を作り、下のプロンプトをそのまま貼り付けてください。

コピペしやすいプレーンテキスト版（GitHub の Raw 表示で全選択できます）:
- 毎日更新: [docs/routine-prompts/daily.txt](routine-prompts/daily.txt)
- 月次フォローアップ: [docs/routine-prompts/monthly.txt](routine-prompts/monthly.txt)

## 作成時に必ずやること

1. **スケジュール**を下表のとおりに設定する
2. **コネクタ（連携）で `Gmail` と `Notion` の両方をオンにする**
   - ここを忘れると、起動したセッションに Gmail / Notion のツールが無く、何もできずに終わります
3. 通知（プッシュ／メール）はお好みで

| Routine | スケジュール | 目的 |
| --- | --- | --- |
| MX CRM 毎日更新 | 毎日 07:00（JST） | メールと Notion 議事録から 最終接点日 / 最終アクション / 次回フォロー予定日 を更新 |
| MX CRM 月次フォローアップ | 毎月 1 日 09:00（JST） | 30日以上接点のない顧客を抽出 → サマリーメール送信 → A/B 顧客の下書き作成 |

> Routines の作成画面では時刻は**ローカル時刻（JST）でそのまま入力**します。UTC 変換は不要です。
> ただし頻度のプリセットは 毎時 / 毎日 / 平日 / 毎週 のみで、**「毎月1日」はプリセットにありません**。
> 月次のほうは一旦「毎週」で作成し、あとから cron を `0 0 1 * *`（UTC）に差し替えます（手順は下記）。

## Routine 1: MX CRM 毎日更新（メール＋Notion議事録）

```text
MX / VRi の顧客CRM台帳（Notion）を、Gmail と Notion 議事録から自動更新するタスクです。日本語で作業し、日本語で報告してください。

## 対象の台帳
Notion データベース「MX / VRi CRM 顧客・接点管理」
- data_source_id: d2334810-dfe0-4b55-b472-15d7f4d20599
- URL: https://app.notion.com/p/dd6c84a357164dd9a7075358a4cff9a5

まず notion-query-data-sources でこのデータソースの全行を取得してください（会社名・メール・ステータス・優先度・最終接点日・最終アクション・次回フォロー予定日 を見ます）。ステータスが「クローズ」の行は対象外です。

## 本人・社内の定義
- 本人のアドレス: taku_yamashita@mxvideo.jp / mmhgf8314@gmail.com
- 社内ドメイン（顧客接点として数えない）: mxvideo.jp / matrox.com / matrox0.onmicrosoft.com / golter.jp

## やること1: Gmail の確認（直近7日）
各行の「メール」欄のドメインについて、直近7日のやりとりを Gmail で検索します（search_threads を使い、newer_than:7d と対象ドメインを組み合わせる。スパム・ゴミ箱は除外）。メール欄が空の行はスキップ。
社内ドメインだけのやりとりは接点として数えません。

最新メッセージが見つかったら:
- 最終接点日 ← そのメッセージの日付（ただし既存の最終接点日より新しい場合のみ更新）
- 最終アクション ← 自分が送った場合は 「[自動更新] こちらから送信「件名」（YYYY-MM-DD）」 / 相手から届いた場合は 「[自動更新] 先方から受信「件名」（YYYY-MM-DD）」

## やること2: Notion 議事録の確認（直近14日）
notion-search / notion-list-recent-pages などで直近14日に更新された議事録ページ（AI議事録を含む。CRM データベース自身の行は除く）を集めます。ページのタイトル・本文に会社名またはその別名が含まれる行を特定してください。
- 会社名の照合は「別名が長いものを優先」で行います（例: タイトルに "Sony Medical" があれば「ソニーメディカル」の行にマッチさせ、「ソニー（放送 / SMOJ）」にはマッチさせない）。
- 会社名の括弧書き（（…） や (…)）より前の部分も別名として扱ってください。
- 議事録の日付は、タイトル内の日付（2026年8月3日 / 2025/07/02 / 20250822 / 251002 など）を優先し、無ければページの作成日を使います。

マッチしたら:
- 最終接点日 ← 議事録の日付（既存より新しい場合のみ）
- 最終アクション ← 「[議事録] タイトル（YYYY-MM-DD）」

## やること3: 次回フォロー予定日
最終接点日を更新した行で、次回フォロー予定日が空欄または過去日になっている場合のみ、「最終接点日 ＋ 30日」に更新してください。未来日が入っている行は触らないこと。

## 更新してよい項目（これ以外は絶対に変更しない）
- 最終接点日
- 最終アクション
- 次回フォロー予定日

ステータス / 次のアクション / 顧客区分 / メーカー / 市場 / 商流 / 製品区分 / 優先度 / 主担当者 / メール / メモ は変更しないでください。行の新規作成・削除もしません。メールの送信・下書き作成もしません（これは更新専用のタスクです）。

## 報告
最後に日本語で簡潔に報告してください:
- 更新した行の一覧（会社名 / 新しい最終接点日 / 最終アクションの要約）
- 議事録は見つかったが台帳のどの会社にも一致しなかったもの（タイトルと日付）— 新規顧客の可能性があるため
- 何も更新がなければ「更新なし」の一行だけでOKです
```

```text

## 報告
```

## Apps Script 版との関係

`src/` 以下の Apps Script（`syncDaily` / `runMonthlyFollowup`）は同じ処理を Google 側で動かすものです。
Routine 版と **どちらか一方だけ**を有効にしてください。両方動かすと同じ行を二重に更新します。

- **Routine 版**: AI議事録（Notion のトップレベルにあるページ）も読める。設定は claude.ai 側だけで完結。
- **Apps Script 版**: Notion インテグレーションを接続したページ配下しか読めないため、AI議事録は対象外。ただし Google 側で完全自動。

Gmail だけ Apps Script、議事録だけ Routine、という分け方は**しないでください**（同じ列を取り合います）。
