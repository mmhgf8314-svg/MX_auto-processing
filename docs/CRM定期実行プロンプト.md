# CRM 定期実行（Routine）用プロンプト

claude.ai の **Routines（定期実行）** 画面で新規 Routine を作り、下のプロンプトをそのまま貼り付けてください。

コピペしやすいプレーンテキスト版（GitHub の Raw 表示で全選択できます）:
- 毎日更新: [docs/routine-prompts/daily.txt](routine-prompts/daily.txt)
- 月次フォローアップ: [docs/routine-prompts/monthly.txt](routine-prompts/monthly.txt)

## 作成時に必ずやること

1. **スケジュール**を下表のとおりに設定する
2. **コネクタ（連携）で `Gmail` と `Notion` の両方をオンにする**
   - ここを忘れると、起動したセッションに Gmail / Notion のツールが無く、何もできずに終わります
3. 通知（プッシュ／メール）はお好みで

| Routine | スケジュール | 目的 |
| --- | --- | --- |
| MX CRM 毎日更新 | 毎日 07:00（JST・プリセット） | メールと Notion 議事録から 最終接点日 / 最終アクション / 次回フォロー予定日 を更新 |
| MX CRM 月次フォローアップ | カスタム `0 0 1 * *`（= 毎月 1 日 09:00 JST） | 30日以上接点のない顧客を抽出 → サマリーメール送信 → A/B 顧客の下書き作成 |

> トリガーのプリセット（1回のみ / 毎時 / 毎日 / 平日 / 毎週）は**ローカル時刻（JST）でそのまま入力**します。
> 「毎月1日」はプリセットに無いので **カスタム**を選び、cron 式を入れます。
> **カスタム欄の cron は UTC** です（日本語での指定は無効）。毎月1日 09:00 JST = `0 0 1 * *`。

## Routine 1: MX CRM 毎日更新（メール＋Notion議事録）

```text
MX / VRi / GM の顧客CRM台帳（Notion）を、Gmail と Notion 議事録から自動更新するタスクです。日本語で作業し、日本語で報告してください。

## 対象の台帳
Notion データベース「MX / VRi CRM 顧客・接点管理」
- data_source_id: d2334810-dfe0-4b55-b472-15d7f4d20599
- URL: https://app.notion.com/p/dd6c84a357164dd9a7075358a4cff9a5

まず notion-query-data-sources でこのデータソースの全行を取得してください（会社名・メール・ステータス・優先度・最終接点日・最終アクション・次回フォロー予定日・次のアクション・メモ を見ます）。ステータスが「クローズ」の行は対象外です。

## 本人・社内の定義
- 本人のアドレス: taku_yamashita@mxvideo.jp / taku_yamashita@matrox.com / tyamashi@matrox.com / taku_yamashita@madokatech.co.jp / mmhgf8314@gmail.com
- 社内ドメイン（顧客との接点としては数えない）: mxvideo.jp / matrox.com / matrox0.onmicrosoft.com / golter.jp / madokatech.co.jp
- ホディノット氏（ajh@golter.jp）、Mingkai Yang、Francesco Scartozzi、Alberto Cieri、convertipsupport@matrox.com（Sandy）などは社内側の人です

## やること1: 顧客とのメール（直近7日）
各行の「メール」欄について、直近7日のやりとりを Gmail で検索します（search_threads を使い、newer_than:7d と対象アドレス／ドメインを組み合わせる。スパム・ゴミ箱は除外）。メール欄が空の行はスキップ。

検索の当て方（重要）:
- 台帳の中でそのドメインを使っている行が1つだけなら、ドメインで検索してよい（同じ会社の別の担当者からのメールも拾えます）
- 同じドメインを使っている行が2つ以上ある場合は、必ずメールアドレスの完全一致で検索すること。ドメインで検索すると別会社の接点を取り違えます
  - 例: 「ソニー（放送 / SMOJ）」と「ソニーメディカル」は別会社ですが、どちらも sony.com です。この2行は必ずアドレス完全一致で扱ってください
- 社内ドメインだけのやりとりは顧客との接点として数えません（ただし「やること3」の対象にはなります）

最新メッセージが見つかったら:
- 最終接点日 ← そのメッセージの日付（ただし既存の最終接点日より新しい場合のみ更新）
- 最終アクション ← 自分が送った場合は 「[自動更新] こちらから送信「件名」（YYYY-MM-DD）」 / 相手から届いた場合は 「[自動更新] 先方から受信「件名」（YYYY-MM-DD）」

さらに、そのメールの本文を読んで「やること4」の内容更新を行ってください。長いスレッドは最新の2〜3通で十分です。

## やること2: Notion 議事録の確認（直近14日）
notion-search / notion-list-recent-pages などで直近14日に更新された議事録ページ（AI議事録を含む。CRM データベース自身の行は除く）を集めます。ページのタイトル・本文に会社名またはその別名が含まれる行を特定してください。
- 会社名の照合は「別名が長いものを優先」で行います（例: タイトルに "Sony Medical" があれば「ソニーメディカル」の行にマッチさせ、「ソニー（放送 / SMOJ）」にはマッチさせない）。
- 会社名の括弧書き（（…） や (…)）より前の部分も別名として扱ってください。
- 議事録の日付は、タイトル内の日付（2026年8月3日 / 2025/07/02 / 20250822 / 251002 など）を優先し、無ければページの作成日を使います。

**マッチした議事録は、必ず次の2種類に分類してください。**

**(a) 顧客が同席していた会議**（顧客との打合せ、デモ、訪問、オンライン会議）
- 最終接点日 ← 議事録の日付（既存より新しい場合のみ）
- 最終アクション ← 「[議事録] タイトル（YYYY-MM-DD）」
- 中身を読んで「やること4」の内容更新も行う

**(b) 社内会議**（Matrox 社内の販売レビュー、パイプライン／Salesforce レビュー、社内定例、本社との打合せ）
- **最終接点日と最終アクションは絶対に変更しない。** 顧客名が出てきただけで、顧客と接触したわけではありません
- 「やること4」のメモと次のアクションにのみ反映する
- 社内会議の中で「先週◯◯社を訪問した」のように**過去の顧客接触が報告されている**場合も、日付が特定できないので最終接点日は動かさず、メモに「【YYYY-MM-DD 社内議事録】…実際の訪問日が分かれば最終接点日を更新すること」と書く

判定の手がかり: 参加者が社内の人（Matrox / golter.jp / ジャパンマテリアル）だけなら (b)。複数の顧客名が並列で出てくる、Salesforce やオポチュニティ、パイプライン、予算の話が中心なら (b)。1社との具体的な技術討議・提案・デモなら (a)。
**迷ったら (b) として扱ってください**（最終接点日を誤って進めるほうが、遅れるより有害です。要フォロー一覧から消えてしまうため）。

## やること3: 社内メール（直近7日）— 顧客名が出てくるものだけ
Gmail で `newer_than:7d` かつ 社内ドメイン（matrox.com / golter.jp / mxvideo.jp / madokatech.co.jp）が絡むスレッドを検索し、件名・本文に台帳の会社名またはその別名が出てくるものを拾ってください。Matrox 本社からの依頼、サポートケース（Case 000xxxxx）、社内での進捗共有などが該当します。

これらについては:
- **最終接点日と最終アクションは絶対に変更しない**（顧客との接点ではないため）
- 「やること4」のメモと次のアクションにのみ反映する

Salesforce の自動通知、社内の全社連絡（IT のお知らせ等）、マーケティングの一斉配信は無視してください。

## やること4: 内容の更新（メモ・次のアクション・ステータス）

### メモ — 追記のみ。既存の本文は絶対に削除・要約・書き換えしないこと
末尾に次の形式で追記します:
`【YYYY-MM-DD 自動】<何があったか、1〜3文>`
- 同じ事実がすでにメモに書かれている場合は追記しない
- 進捗がない、または「案内メールを送った」程度で内容がない場合は追記しない
- メモが 2000 文字を超えそうな場合は、最も古い「【… 自動】」の段落から削って収める（手入力の部分は残す）

### 次のアクション — 書き換えてよい
- 書き換える前に既存の内容を読み、**まだ完了していない依頼・約束・宿題が書かれていれば、それを新しい文に必ず引き継ぐ**こと
- 状況が変わっていなければ書き換えない
- 先方の返事待ちなのか、こちらのボール（返信・資料送付・日程連絡）なのかがわかるように書く。こちらのボールで期限を過ぎているものは文頭に「【期限超過】」を付ける

### ステータス — 前に進む方向にだけ変更してよい
`リード → 初回接触 → 商談・提案中 → 評価・PoC中 → 受注・納入` の順で、進んだと明確に判断できる場合のみ更新します。
- 後退させない（例: 評価・PoC中 → リード にはしない）
- **「クローズ」には絶対にしない**
- 「保留・様子見」への変更もしない
- 変更したら、報告に必ず理由を書く

## 変更してはいけない項目
優先度 / 顧客区分 / メーカー / 市場 / 商流 / 製品区分 / 製品・案件 / 主担当者 / メール / 会社名 は変更しないでください。行の新規作成・削除もしません。メールの送信・下書き作成もしません（これは更新専用のタスクです）。

## やること5: 次回フォロー予定日
最終接点日を更新した行で、次回フォロー予定日が空欄または過去日になっている場合のみ、「最終接点日 ＋ 30日」に更新してください。未来日が入っている行は触らないこと。

## 報告
最後に日本語で簡潔に報告してください:
- 更新した行の一覧（会社名 / 新しい最終接点日 / 何を更新したか）
- ステータスを変えた行があれば、その理由
- 「【期限超過】」を付けた行の一覧（こちらのボールが止まっているもの）
- 議事録は見つかったが台帳のどの会社にも一致しなかったもの（タイトルと日付）— 新規顧客の可能性があるため
- 何も更新がなければ「更新なし」の一行だけでOKです
```

## Apps Script 版との関係

`src/` 以下の Apps Script（`syncDaily` / `runMonthlyFollowup`）は同じ処理を Google 側で動かすものです。
Routine 版と **どちらか一方だけ**を有効にしてください。両方動かすと同じ行を二重に更新します。

- **Routine 版**: AI議事録（Notion のトップレベルにあるページ）も読める。設定は claude.ai 側だけで完結。
- **Apps Script 版**: Notion インテグレーションを接続したページ配下しか読めないため、AI議事録は対象外。ただし Google 側で完全自動。

Gmail だけ Apps Script、議事録だけ Routine、という分け方は**しないでください**（同じ列を取り合います）。
